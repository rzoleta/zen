Zen: V1 plan

A Japanese vocabulary app that ships the method in the learning spec as a product: Kaishi 1.5k, FSRS, pass/fail, immersion-first philosophy, none of the setup. The app is called Zen everywhere (repo, code, screens); the keyword-heavy App Store title is a release-time decision.

Scope

V1 is one PR. Local-only, no accounts, no server, no purchases. iOS-first: the code stays cross-platform-clean (no iOS-only API without a guard and a plain fallback), but only iOS gets tested and polished. Everything below the "later PRs" line is out.

1. Features

This section is design-agnostic: what the app does, not how it's built.

The deck

  • Ships with Kaishi 1.5k built in. No deck browsing, no imports in V1; the deck is the app.
  • New cards are introduced in Kaishi's deck order, which is already frequency-sorted.
  • Kaishi is credited in Settings → About. Before shipping we verify its license permits redistribution inside an app (it's a community deck built on Core/Tango material).

The review loop

Anki semantics, not consumer-app sessions. One daily queue: every due card plus up to N new cards (default 10, user-settable). No review cap. Done means the queue is empty, and the app says so. Cards in learning resurface after their 10-minute step, including within the same sitting.

  • Scheduling is FSRS with desired retention defaulting to 0.90.
  • Grading is binary: pass or fail. No Hard, no Easy, anywhere.
  • The day rolls over at 4am local time, like Anki, so a midnight session doesn't leak tomorrow's cards.
  • A card that lapses 8 times by default auto-suspends as a leech and shows as "suspended (leech)" in the Words tab. The user can unsuspend it there and configure the lapse threshold under Daily review in Settings.

The card

Flashcards should feel like physical cards. The flip is a real 3D rotation, not a crossfade.

  • Front: the word, with its example sentence below in smaller type, target word highlighted.
  • Back: word with furigana reading and an audio play button, meaning, sentence translation with an audio play button. No pitch accent graph, no image.
  • Tap to flip. After flipping: swipe up = pass, swipe down = fail. Swipes are inert before the flip.
  • Left-to-right swipe (like the back gesture) undoes the last grade, one step.
  • Word audio autoplays on flip (toggleable in Settings). Sentence audio is tap-only.

Screens

Four native tabs. The review session itself is a full-screen modal over everything, no tab bar, which also keeps the undo swipe clear of the navigation back gesture.

TabContents
HomeToday's queue summary ("12 reviews · 10 new"), a single prominent start button, and the done state when the queue is empty.
WordsAll 1,500 words in deck order: word, reading, meaning, status chip (new / learning / mature / known / suspended). Learning includes review intervals below 21 days; mature starts at 21 days. Search and status filter. Tapping opens a detail view with the full card contents and FSRS stats (next due, interval, lapses), plus per-word actions: suspend, mark known, reset. Multi-select is a later PR.

FSRS internals (weights, steps, optimizer) stay hidden.

Look and feel

  • Clean, minimal, modern. Vercel/OpenAI, not Duolingo. Generous whitespace, restrained color, type does the work.
  • Light and dark themes, both first-class, following the system setting.
  • Liquid Glass (via Expo's glass views) on chrome where it earns its place: tab bar, modal headers, overlay controls. Guarded, with a plain fallback for older iOS and Android.
  • Japanese text renders in the user's chosen font: Noto Serif JP (Mincho) or Noto Sans JP (Gothic), bundled.

Later PRs (noted, not designed)

  • Import via the share sheet: sharing text to Zen opens a card creator. Other import paths (image) may follow.
  • Word groups (Numbers, Greetings, Family…) with manual drilling.
  • Multi-select in the Words tab to bulk-change status (e.g. mark all greetings known).
  • Android test/polish pass. Backup/sync. FSRS parameter optimization from the user's own review log.

Architecture

Three layers, with the scheduler as the only place FSRS is spoken:

  1. Content pipeline (build time). scripts/extract-kaishi.ts runs once on a developer machine: unzips the .apkg (it's a zip with a SQLite db inside), reads the 1,500 notes, strips fields we don't ship (pitch accent, pictures), renames audio to word_0001.mp3 / sentence_0001.mp3, and emits assets/deck/kaishi.json plus assets/deck/audio/. Output is committed; the script never runs on device or in CI.
  2. Data + scheduler (runtime, UI-free). Drizzle schema, first-launch seeding from the bundled JSON, and a scheduler/ module wrapping ts-fsrs. This module owns queue building, grading, undo, the 4am day boundary, and leech auto-suspension. It exposes maybe six functions and is where all the Jest tests live. No React imports allowed in this layer.
  3. UI. expo-router screens and components. Reads via Drizzle live queries, writes via the scheduler module. The review modal holds its session in a Zustand store (current queue, current card, flip state) and commits each grade to SQLite immediately, so killing the app mid-session loses nothing.

Data model

TableColumns (essentials)
wordsid, deck_order, word, word_furigana, meaning, sentence, sentence_furigana, sentence_meaning, word_audio, sentence_audio. Immutable content, seeded once.
cardsword_id, FSRS state (state, due, stability, difficulty, reps, lapses, last_review), suspended (none / manual / leech), known flag. One card per word, created at seed time.
review_logid, card_id, rating, previous card state snapshot, reviewed_at, duration_ms. Append-only. Powers undo (restore the snapshot), the heatmap, retention, and future parameter optimization.
settingskey/value. new_per_day, desired_retention, autoplay, jp_font.

Storing the pre-review snapshot in the log makes undo a one-row restore instead of a scheduler replay, and it means we never lose information FSRS optimization will want later.

Scheduler details worth writing down

  • ts-fsrs is configured with a single 10-minute learning step and desired retention from settings. Changing retention in Settings affects future scheduling only; no mass reschedule in V1.
  • "Due today" means due < next 4am local. All queue and stats code goes through one currentStudyDay() helper; nothing else touches dates. This is the most test-worthy code in the app.
  • Queue order: learning cards ready now, then due reviews, then new cards in deck order. New cards stop appearing once the daily count is hit; the count resets at 4am.
  • "Mark known" is its own flag, not a fake review, so stats stay honest.

Known risk: deck redistribution. The generated deck is 73.40 MiB and an iOS production export is 96 MiB, so V1 bundles it. The official Kaishi repository still has no license file. Redistribution permission must be confirmed before publishing the app.

3. Action plan

One PR, built in phases that each leave the app runnable. Phases 2 and 3 are the ones where correctness matters; everything after is screens.

Phase 0: content

  • Verify Kaishi's license for in-app redistribution; record the finding and required attribution.
  • Write scripts/extract-kaishi.ts, generate kaishi.json + audio, commit, and measure total size. Decide bundled vs first-launch download per the risk note.

Phase 0 completed on September 7, 2026. The extractor is implemented and verified against Kaishi v2.4.2. V1 now bundles its 1,500 vocabulary records and 2,999 generated audio files, totaling 73.40 MiB. The official Kaishi repository has no license, and its content draws from other Core, Tango, and AJT Japanese sources, so publishing still requires redistribution approval.

Phase 1: skeleton

  • Set up the monorepo (root package.json with npm workspaces, apps/mobile and an empty apps/web placeholder), then scaffold Expo (latest SDK) in apps/mobile: expo-router with the four native tabs plus the review modal route, NativeWind with light/dark theme tokens, bundled fonts.
  • Placeholder screens that prove navigation, theming, and fonts end to end.

Phase 2: data and scheduler

  • Drizzle schema + migrations, first-launch seeding of 1,500 words and cards.
  • Scheduler module over ts-fsrs: buildQueue, grade (pass/fail), undo, 4am boundary, leech auto-suspend.
  • Jest tests: interval sanity against known FSRS behavior, queue composition and ordering, new-card limit reset at 4am, undo round-trip, leech trigger at lapse 8 and configurable thresholds.

Phase 3: the review session

  • Card component with the 3D flip, both faces per the card spec, furigana rendering, chosen Japanese font.
  • Gestures: tap to flip, swipe up/down to grade (post-flip only), left-to-right undo. Grade commits to SQLite immediately.
  • Audio: word autoplay on flip, tap-to-play buttons, next-card preload.
  • Session flow: launch from Home, learning cards resurface, queue-empty done state.

Phase 4: the other screens

  • Home: live queue counts, start button, done state.
  • Words: list with search and status filter, detail view with FSRS stats, suspend / mark known / reset actions.
  • Progress: heatmap, counts and time, deck status bar, true retention.
  • Settings: the four settings, About with credits, reset-progress with confirmation.

Phase 5: polish and QA

  • Glass surfaces where appropriate, haptics on grade, empty and edge states, app icon, both themes swept screen by screen.
  • Manual QA against a checklist: fresh install → seed → first session → force-quit mid-session → relaunch → undo → leech path → reset progress → day rollover (device clock).

Done means

  • A fresh install reviews Kaishi correctly for days without touching a network.
  • Scheduler tests green; intervals match what the learning spec's FSRS section predicts for pass/fail patterns.
  • Every V1 feature above exists; every "later PR" item still doesn't.
